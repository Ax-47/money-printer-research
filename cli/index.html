    Commands¶

    Every command is a console script declared in pyproject.toml under [project.scripts]. Run them with uv run <name>. They take no arguments; everything they read comes from the settings.

    Command Entry point What it does
    collect_data data_collection.collect_data Download the Understat schedule, football-data.co.uk odds, Understat player stats and the Transfermarkt tables. See Collect.
    clean_data clean_data.exec_clean_data Clean the collected files and build the pre-match features; write nine CSVs. See Clean and Features.
    check_clean schema.check_clean Validate every CSV in the clean output folder against its schema.
    feature_importance analysis.exec_feature_importance Forward feature selection for the home / draw / away model on model_frame.csv, walk-forward by season.
    modeling analysis.exec_modeling Compare home / draw / away models on the selected features, check the baseline's calibration, score them on the held-out seasons, then save the logistic model.
    predict analysis.exec_predict H/D/A probabilities for every unplayed fixture in the schedule, from the saved model.
    backtest analysis.exec_backtest Bet the model's best-EV outcome against historical bookmaker odds, season by season, and report profit and ROI.
    notebook notebook.exec_notebook Open JupyterLab at the project root with the project's environment.
    show_config config.show_config Print the settings in effect and the file they came from. See Configuration.
    api api.exec_api Start the HTTP API. See Docker and API.

    Entry points are imported only when called, so importing the package (for example money_printer_research.clean_data in a notebook) does not load the scraping libraries.

    collect_data¶

    Runs the four collectors, fastest first:

    1. collect_schedule: one Understat request per league and season.
    2. collect_odds: one football-data.co.uk CSV per league and season, for backtest.
    3. collect_player_stats: one Understat page per match.
    4. collect_transfermarkt: one DuckDB download, then three Parquet exports.

    A file that already exists is skipped, and a file is written only after it passes its raw schema check, so an interrupted or failed run can simply be started again. Failures for one league and season are printed as FAILED and the run carries on with the next.

    clean_data¶

    Runs clean, writes its four CSVs, then runs extract_features and writes five more. If a step fails, the command raises with that step's error; the clean CSVs stay on disk even when feature extraction fails.

    check_clean¶

    Reads each CSV listed in schema.CLEAN_FILES with the dtypes of its schema (CSV loses some, such as season), validates it, and prints one line per file:

    ok      match_leagues     123,456 rows
MISSING data/clean/players.csv
FAIL    elo: ...

    Exits with status 1 if any file is missing or fails.

    feature_importance¶

    Reads model_frame.csv and selects feature groups for a multinomial logistic regression by greedy forward selection from Elo: each step adds the group that lowers the walk-forward log loss (seasons 2021 to 2023, each predicted by a model fitted on the seasons before it) the most, until no group gains MIN_GAIN. It then scores Elo alone, the selection and every group once on the held-out seasons from 2024, and says so if the selection differs from SELECTED.

    modeling¶

    Fits each model in analysis.modeling.MODELS on the SELECTED features, on the same walk-forward seasons, and prints log loss, ranked probability score, Brier score and accuracy; then the logistic baseline's calibration by probability decile; then every model once on the held-out seasons from 2024. Last, it refits the logistic model on every season and saves it with joblib to modeling.out_file (data/models/hda_logistic.joblib); analysis.modeling.load_model reads it back and its predict takes model_frame rows. joblib runs code from the file, so load only models you saved yourself.

    predict¶

    Loads the model modeling saved and predicts every fixture the Understat schedule holds but has not seen played (is_result false), then writes game_id, date, league, both teams, p_H, p_D and p_A to modeling.predictions_file (data/predictions/upcoming.csv). Run modeling first.

    Each fixture's features come from match_features.csv, using only what is known before kick-off:

    • Elo: each team's rating after its last played match; promoted teams start a new season the way clean_data starts them.
    • Games in the last 14 days: league games only (played ones and earlier fixtures), so a cup or European game in that window is missed.
    • Player slots: the line-up is unknown before kick-off, so a team gets the starters of its last played match and their values from then: the likely XI, one game old.

    The schedule covers the seasons from understat.start_year up to, not including, understat.end_year. To predict the season in progress, set end_year past it (UNDERSTAT__END_YEAR=2027 for 2026-27) and run collect_data and clean_data. collect_data skips a schedule file that already holds every season, so delete data/raw/xg_schedule.csv to pick up newer results and fixtures.

    backtest¶

    Reads the football-data.co.uk 1X2 odds collect_data downloaded to modeling.odds_dir, predicts every season from modeling.backtest_from with the logistic baseline fitted only on the seasons before it, and prices each game with Pinnacle's closing odds (falling back to Pinnacle's early price, the market average at closing, then Bet365's early price). Every other price in the files (all bookmakers, early and closing, Asian handicap and over/under 2.5) is available from analysis.odds.read_prices; see Bet schemas.

    Each game's pick is the outcome with the highest expected value of a 1-unit stake, p * odds - 1. It prints the model's and the bookmaker's log loss and, for a few EV thresholds, the bets, hit rate, profit and ROI of betting every pick above it, and writes every game to modeling.backtest_file (data/predictions/backtest.csv). Needs data/clean/model_frame.csv, as modeling does, and the odds from collect_data. The web page at /backtest.html shows the same with a threshold slider.

    football-data names teams differently from Understat; each name is matched to the team it shares the most match days with, so there is no alias list to keep.

    market_test¶

    Can a model forecast results better than the betting market? Reads only the football-data.co.uk files collect_data downloaded (prices, results, shots on target), so it does not need the Understat pipeline.

    It removes the bookmaker's margin from Pinnacle's early and closing 1X2 prices (proportional, power and Shin methods, compared), then scores five forecasters on every game from 2016/17, each season predicted only from the seasons before it:

    Forecaster What it is
    early Pinnacle's early price, margin removed: what a bettor can act on
    close Pinnacle's closing price, margin removed
    market_refit The early price recalibrated by a logistic regression
    market_and_form The early price plus team form: Elo, recent goals and shots on target
    form_only Team form without the market

    It prints each one's mean log loss and RPS, and for the pairs in market.COMPARISONS the mean per-game difference with a 95% interval. A model beats the market only if that interval is entirely below zero.

    strategies¶

    Runs every strategy in strategies.toml (modeling.strategies_file), the pre-registered suite: written before any strategy was run, and changed only in commits that say so. It prints the commit of the file it ran with.

    Each strategy is a rule for which bets to place at which price: back the favourite, always the draw, the model's best EV above a threshold, any price that beats Pinnacle's margin-free probability (line shopping), and so on, over 1X2, Asian handicap and over/under 2.5. Every bet is 1 unit, settled from the score; Asian handicap quarter lines split the stake.

    For every variant (a strategy with one parameter value) and league it reports:

    Column Meaning
    roi profit per unit staked, with its 95% interval
    close_ev expected profit per unit if Pinnacle's closing price is right: a far less noisy measure of edge than profit
    p_value, q_value one-sided test of ROI above zero, and the Benjamini-Hochberg q-value over every cell of the suite

    and, per strategy, the ROI when each season uses the parameter value that made the most on the seasons before it.

    Prices whose implied probabilities sum to under 0.97 (an arbitrage of 3% or more) are dropped as data errors, mostly in football-data's best-price columns.

    staking¶

    Runs the strategy suite, then replays the bets of a few variants (staking.STAKED) in date order from a bankroll of 1 under each staking plan:

    Plan Stake
    flat 1% of the starting bankroll
    kelly, half_kelly, quarter_kelly the Kelly fraction of the current bankroll, using the probability the strategy bets on, and half or a quarter of it
    martingale 1% of the start, doubled after each loss and reset after a win

    A bankroll at 1% of its start is ruined and stops. It prints the history that happened (final bankroll, maximum drawdown, lowest point) and, over 1,000 resampled histories of 1, 3 and 5 seasons, the chance of losing half and 90% of the bankroll at some point.

    practicality¶

    For the variants with a positive expected value at the closing price (line shopping), it prints:

    • how many seasons of betting it takes before an edge of that size shows as profit two standard errors above zero, and what it earns per season at 1 unit a bet
    • what is collected when soft bookmakers close each account once it is a few stakes up
    • the same rule on the Betfair exchange, which does not close winners, after commission

    report¶

    Runs market_test, strategies, staking and practicality from the raw football-data files and writes one self-contained HTML page to modeling.report_file (data/report/report.html). The page:

    • answers whether any of it beats the market, in sentences built from the numbers
    • names the commit of the code and of strategies.toml it ran with, so the page can be rebuilt
    • holds every table and chart from those commands

    The only hand-written text is the method and the limitations. It also writes the same results as JSON to modeling.analysis_file, which the API serves at GET /analysis and the /analysis.html page shows, with a league filter for the strategies.

    notebook¶

    Starts JupyterLab with the project root as the notebook directory. The analysis notebooks live in notebooks/.
